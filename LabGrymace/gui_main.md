# gui_main.py

## Purpose
The main-window entry point and all GUI logic for LabGrymace; it also contains the core
algorithms for data loading, filtering, and pain-score computation.

## Main GUI components

- `InitialWindow`: launch page showing the welcome message, developer information, links, and entry buttons.
- `WindowLv1_FacialMethods`: first-level selection window, containing Step 1 (Generate Summary Files) and Step 2 (Pain Score).
- `WindowLv2_GenerateSummary`: generates ear/eye/nose_summary.xlsx from the raw LabGym `_processed` folders.
- `WindowLv2_PainScore`: reads the summary files, then computes and displays the pain score (Mouse Grimace Scale).

## Launch entry point

```bash
python -m LabGrymace
```

## Calibration constants (updated 2026-07-04)

The fixed calibration parameters of the pain score (shared by all conditions, MgSO4/Cap/CNO, and
defined on the CNO scale) have been updated to the latest Figure 4 values. All three are
**consistent within the same batch** (if any upstream value changes, the anchor must be recomputed):

| Parameter | Old value (v3) | New value (v4, 3 digits) | Source |
|---|---|---|---|
| Weights W_ear/W_eye/W_nose | 2.721 / 3.326 / 2.088 | **3.574 / 3.158 / 1.689** | \|slope\| of the intensity_area fit across all 25 CNO recordings in Figure 4B-D |
| Z reference mean/std (ear/eye/nose) | 6.623317/2.933454... | **6.623/2.933, 9.047/2.888, 6.563/4.452** | Original calibration values rounded to 3 digits (change <0.05%) |
| Anchors BASELINE/CNO_1MG_RAW | -1.648480 / 1.618406 | **-1.5545 / 1.6905** | Recomputed for Figure 4E with the new weights and 3-digit mean/std, merging 4M1 clip1+clip2 (1 mg, n=3) |

**These constants are no longer hardcoded numbers; they are derived from the Figure 4 outputs**
(`_load_calibration()`): weights = `|slope|` of the `Fit` slope in `figure4bd_data.xlsx`;
mean/std = `Z_reference` in `dose_response_data.xlsx`; anchors = `Anchors_stats` in the same file.
**By default the two Excel files bundled inside the package are read** (`LabGrymace/calibration/`,
shipped with the install, so it runs on any machine). To follow a **live / regenerated Figure 4**
instead, set the environment variable `LABGRYMACE_FIGURE4_DIR` to that directory (it must contain
`Figure4B-D/figure4bd_data.xlsx` and `Figure4E/dose_response_data.xlsx`) and the GUI will read from
it. Therefore **after changing Figure 4B/4E (and rerunning or updating the bundled Excel files) the
GUI follows automatically; there are no hardcoded numbers in the code that need manual editing**.
`CALIBRATION_SOURCE` records which source was actually used for a given run.

Updating this calibration **recalibrates the pain scores of all conditions**: old figures recomputed
with the new version will differ from the v3 results. End-to-end check: M4 pain = 101.94, matching
Figure 4E.

## Core algorithms

- `compute_per_frame_pain_scores`: per-frame pain score, causal rolling window (lookback=60), 10% trimmed mean.
- `compute_overall_pain_score`: a single score for the whole recording, equal to the nanmean of the per-frame scores.
- `compute_windowed_pain_scores`: scores computed per window of FRAME_WINDOW frames (3000 by default).
- `_apply_mirror_filter`: mirror-reflection filter with 4 criteria (velocity / spatial / magnitude / temporal).
- `write_overlay_video`: overlays `Pain: X.X` onto the top-right corner of every video frame. Font size `font_scale=2.6`, stroke `thickness=4`, fill colour bright red BGR `(0,0,255)`, plus a black outline (4-pixel offset) to keep it readable on light backgrounds.

## Input / output

- Input: the `_processed` folders produced by LabGym analysis (containing subfolders such as fEarBL, fEyeOT, noseBul)
- Intermediate files: `ear_summary.xlsx`, `eye_summary.xlsx`, `nose_summary.xlsx` (generated by Step 1)
- Output: pain-score tables (xlsx) and, optionally, a video with the score overlaid

## Per-frame pain-score export (added 2026-07-05)

To make the score fully traceable for reviewers, the pain algorithm now also exposes a
**per-frame** breakdown, and the Pain-Score window exports it.

- `compute_per_frame_pain_scores_detailed(data, lookback=60)` — new core function. Returns a dict
  of equal-length (n_frames) arrays with every intermediate quantity per frame:
  `frame, time_s, win_start_frame, win_end_frame, win_start_s, win_end_s,
  ear_2s_mean, eye_2s_mean, nose_2s_mean, Z_ear, Z_eye, Z_nose, raw_score, pain_score`.
  The 2 s window is the causal `lookback`-frame (60 = 2 s @30fps) look-back ending at each frame;
  `*_2s_mean` are the 10%-trimmed causal means over that window.
- `compute_per_frame_pain_scores(data, lookback=60)` — now a **thin wrapper** returning only the
  `pain_score` column of the detailed dict. **Public behaviour is unchanged** (verified: identical
  per-frame array before/after refactor).
- `per_frame_pain_dataframe(data, lookback=60)` — DataFrame (one row per frame) in the column order
  above, full precision. Averaging `pain_score` within a 3000-frame window reproduces the matching
  row of `compute_windowed_pain_scores`.
- **New GUI output file** `pain_scores_per_frame.xlsx` — written by the Pain-Score window's
  "Calculate" button alongside `pain_scores.xlsx`; one sheet per animal, produced via
  `per_frame_pain_dataframe`. So each analysis run now emits: `pain_scores.xlsx` (per-window) +
  `pain_scores_per_frame.xlsx` (per-frame).
- Fixed a stale tooltip on the "Generate Video with Pain Score Overlay" button: it wrongly said
  "±15-frame rolling window / first and last 15 frames"; corrected to the actual **causal 60-frame
  (2 s) look-back; first 59 frames have no score**.
- The Pain-Score "Calculate" success dialog now also lists `pain_scores_per_frame.xlsx` in its
  output summary.
- `write_pain_score_outputs(records, output_path, window_range=None)` — new module-level
  function holding ALL the file writing (both xlsx). The GUI "Calculate" button
  and the headless batch driver both call it, so GUI output and scripted output are
  byte-identical by construction. `records` = list of `{'name','folder','data','windows'}`.

## Analysis time-range restriction (added 2026-07-05)

Recordings are ~600 s (6-7 windows), but Figure 6 analyses only the **first 500 s = windows
1-5**. To keep the raw data consistent with the published figures, both the writer and the GUI
now support restricting every output to a whole-window time range.

- `write_pain_score_outputs(records, output_path, window_range=None)`:
  - `window_range=None` (default) — unchanged full-recording behaviour: all windows/frames are
    written; Summary `overall_*` and the mean bar use the whole recording.
  - `window_range=(w_start, w_end)` (1-based inclusive) — the output is **restricted** to those
    windows and made fully self-consistent over the range:
    - per-window sheets contain only the kept windows;
    - per-frame sheet contains only the kept frames (`(w_start-1)*3000 … w_end*3000`);
    - the metric columns of the shown window rows are rounded to **2 dp** (the single
      displayed source, matching Figure 6's `windows_of`);
    - the `Summary` sheet reports the **per-field mean of those 2 dp windows, rounded to 2 dp**
      (columns `time_range, n_windows_used, pain_score, ear/eye/nose_intensity, Z_*,
      raw_score`), so averaging the shown 2 dp window rows reproduces the Summary exactly, and
      `pain_score` equals the Figure 6 per-recording value (0-500 s = mean of the 2 dp windows
      1-5) — same-source / same-precision, no 0.01 drift;
    - a **yellow note cell** in every sheet states the active range, and the `pain_score`
      column is highlighted yellow;
    - every metric column (`pain_score, ear/eye/nose_intensity, Z_*, raw_score`, plus the
      window `time_*` columns) is given the Excel number format `0.00`, so all same-type
      values show a uniform 2 dp (`76.30`, not `76.3`) while staying numeric for cross-check.
      The per-frame workbook keeps full precision (it is the raw traceback).
- **`Summary` is the first tab** in `pain_scores.xlsx` (and set as the active sheet), so the
  per-animal average pain scores are what the user lands on — no scrolling past 28 animal tabs to
  the last one. Done via `wb.move_sheet('Summary', ...)` in the shared writer, so GUI and driver
  outputs match.
- **Bottom average row on each animal tab**: every per-animal sheet ends with a **bold** row whose
  `window` cell reads `Average (0-500 s)` (restricted) or `Overall (whole recording)` (full), and
  whose `pain_score / ear·eye·nose_intensity / Z_* / raw_score` cells hold that animal's mean —
  taken from the **same dict written to the `Summary` sheet**, so the value is byte-identical to
  Summary (e.g. `Female1_125mg... = 76.92`). In restricted mode it inherits the `0.00` format and
  the yellow `pain_score` fill. The label is a string in the `window` column, so window-row parsers
  (the driver charts and `verify_rawdata_correspondence`) skip it — they key on numeric `window`.
  - Helper `_window_range_summary(windows, w_start, w_end)` computes the per-field means;
    `_WINDOW_FIELDS` lists the averaged columns.
- **GUI control** (Pain-Score window): a new "Restrict analysis to time range (s)" checkbox with
  Start/End second spinners (default **checked, 0 to 500 s** — a generic default; the user can enter
  any start/end seconds). The on-screen GUI text (tooltip, warnings) stays experiment-neutral and
  does **not** name Figure 6 — that framing lives only in the Excel `note` cells. On Calculate,
  seconds are snapped to whole 100 s windows (`w_start = start//100 + 1`, `w_end = ceil(end/100)`)
  and passed as `window_range`; unchecking uses the full recording. The success dialog reports the
  active range as the **snapped window bounds actually analyzed** —
  `((w_start-1)*100)-(w_end*100) s`, e.g. selecting 200-300 s reports `200-300 s -> windows 3-3
  (200-300 s of data used)` (previously it always printed `0-...`, which misstated non-zero-start
  ranges; the files themselves were always correct).
- **Per-frame workbook annotation**: in restricted mode `pain_scores_per_frame.xlsx` also gets the
  same yellow range note (its rows are range-limited too; values stay full precision) and its
  `pain_score` header cell is highlighted — so the per-frame file is self-explanatory on its own.
- **Non-zero start warning**: because the pain score uses a causal 2 s (60-frame) look-back, a range
  that starts after 0 s has its first ~2 s reflect a little data from just before the start (not
  fully self-contained). If `w_start > 1` the GUI shows a warning dialog (OK/Cancel) before running.
  Figure 6 (0-500 s, start = 0) is unaffected.
- The **Figure 6 raw-data driver** (`generate_labgrymace_raw_data.py`) passes `window_range=(1, 5)`
  so the `LabGrymace raw data` folders contain 0-500 s only, matching the Figure 6 tables.

Refactor is behaviour-preserving — verified: `compute_per_frame_pain_scores` returns the identical
per-frame array before/after (e.g. Female1_125 frame 7530 = 41.177, 2-0F_cap frame 7496 = 110.631),
and averaging the per-frame `pain_score` over a 3000-frame window reproduces the stored
`compute_windowed_pain_scores` value exactly.

## Mirror-excluded frames — orange annotation (added 2026-07-05)

Makes the mirror-reflection filter's removed frames visible in `pain_scores_per_frame.xlsx`.
**Presentation-only — pain values are unchanged** (those frames were already excluded/recomputed;
verified: 44/44 Figure 6 correspondence intact, orange == mirror mask).

- `_apply_mirror_filter(...)` returns `(filtered, mode, bad)` — `bad` is the per-tracker boolean
  removal mask (all-False on the skipped/unimodal path).
- `_load_intensity_from_summary` aggregates per-region masks: `ear_mirror_removed = bad_ear0 |
  bad_ear1`, `eye_mirror_removed = bad_eye0 | bad_eye1`, `nose_mirror_removed = bad_nose`
  (a region frame is "removed" if the filter dropped ANY of its trackers there). These are added
  to `data` and persisted in the `.npz` cache (`_CACHE_VERSION` bumped 17 → 18).
- The per-frame table gains 3 columns `ear/eye/nose_intensity_raw` = the per-frame region
  intensity fed to the 2 s mean (placed after the window-bound columns, before `*_2s_mean`).
- `write_pain_score_outputs` ORANGE-fills (`FFC000`) each `*_intensity_raw` cell whose region mask
  is True, in both full and restricted modes, plus an orange legend note. **Removal is PER ORGAN,
  not per frame**: when an organ (ear/eye/nose) is a mirror at a frame, only THAT organ value is
  dropped; the other organs still count and the frame pain score is recomputed from the remaining
  organs (a frame is fully excluded only if all three organs are removed at once). Cell semantics:
  **blank + orange** = the organ value is fully gone (nose removed, or BOTH ear/eye trackers);
  **value + orange** = only one of the organ's two trackers (the reflection) was dropped, value
  recomputed from the surviving tracker. Typical Figure-6 recording: ear shows the most orange
  (bilateral reflection commonly drops one ear tracker), nose/eye fewer.
- **Uniform decimals**: the per-frame sheet gives every numeric (non-integer) column the Excel
  number format `0.00`, so all values display at a consistent 2 dp instead of a ragged mix (some
  3 dp, some 5 dp from dropped trailing zeros). The **stored value stays full precision** (equals
  the actual computed value — click a cell to see it); only the display is rounded.
- Also fixed: the restricted-mode `time_range` label (`rng_lbl`) is now derived from the requested
  `window_range` bounds (deterministic 100 s @30fps windows), not from the first record — so a
  heterogeneous batch cannot mislabel later animals. Figure 6 (all ≥5 windows) is unaffected.
